Maturity Ladder

1

Individual use, no shared standards

Ad hoc
Engineers use AI tools on their own terms. Output quality tracks individual skill at managing context, nothing transfers between people.
Looks like
Prompting knowledge lives in one person's history · No repo-level instruction file, or one written once and never pruned · Tool choice varies by engineer · Bimodal results nobody can explain
To advanceWrite the repo instruction file and put it under PR review like any other source file.
2

Shared instruction files, review policy stated

Consistent
Context is a versioned team asset and the review bar is explicit. The author of a PR owns every line in it regardless of who typed it.
Looks like
Build, test and lint commands in the instruction file so the agent verifies itself · Directory-level files where subsystems differ · An explicit do-not-touch list · Updating conventions includes updating the file
To advanceDefine agent write scope, credential scope, and what CI blocks before a human ever sees it.
3

Shared command library, permissions defined, CI gates enforced

Governed
The org's best prompts are checked-in assets, agent authority is bounded by design rather than by convention, and machine-checkable failures never reach human review.
Looks like
Agents push to branches, never to main, and never self-merge · Short-lived scoped tokens, never production · Approved MCP / tool registry, with fetched content treated as untrusted input · Tests derived from spec, not from the implementation
To advanceCapture a baseline now (cycle time, revert rate, churn, PR queue depth) before adoption deepens.
4

Measured against a baseline, patterns documented, adoption deliberate

Deliberate
Change is evaluated against evidence and baseline, and the practices that produce results are transferable instead of resident in a few engineers.
Looks like
Cycle time, change failure rate, code churn and review latency trended against a pre-adoption baseline · Named pattern-library owners · Champions given explicit time to transfer their working loop · Acceptance rate and seat utilization ignored
Watch forReview capacity, not generation, is the ceiling — it shows up as queue depth long before it shows up as an incident.
Four questions that place a team on the ladder
What is in your repo instruction files today, and when were they last pruned?
What can an agent write to without a human in the path?
How does your PR queue depth compare to six months ago?
Who is getting the most out of this, and what are they doing differently?
