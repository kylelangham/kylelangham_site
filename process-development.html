Process Development

Compare runs and see which parameter moved with which attribute

An agent that pulls every parameter trace and every offline result across a campaign, aligns the runs on process time, and shows where the runs actually diverged and what moved with it.

What this looks like today

Run 4 is down eighteen percent and everyone has a theory.

The campaign is four engineering runs in and the titer on run 4 is down eighteen percent against run 2. In the debrief there are five plausible explanations and no way to test any of them quickly. The seed train was a day longer. The feed started at a different cell density. There was a pH excursion around hour 60 that was within range and therefore never flagged. A different lot of media was used.

Checking any one of those means going to the historian for the parameter traces, to the LIMS for the offline assays and the release attributes, and to the batch record for what the operators actually did rather than what the protocol said. Then aligning four runs that started at different clock times onto a common process time axis, in Excel, by hand.

That is roughly a week per comparison, which means it happens for the runs that fail dramatically and not for the ones that drift quietly. The comparisons you skip are where the process knowledge was.

The demo

Four runs, aligned on process time, parameters against attributes.

The agent is given a set of run identifiers. It pulls every continuous parameter trace and every offline and release result for those runs, aligns them on elapsed process time rather than clock time, then reports where the runs materially diverged and which quality attributes moved alongside each divergence.

Under the hood

Alignment first, because everything downstream depends on it.

Most manual run comparisons go wrong at the alignment step, not the analysis step. Runs inoculated at different times of day, holds of different lengths and different seed train durations mean a straight clock-time overlay compares hour 40 of one run against hour 52 of another. The agent does the alignment as a deterministic transform before anything else happens.

  • Historian and MES for the continuous traces across every run in the set: pH, dissolved oxygen, temperature, agitation, feed rate, gas flow and vessel weight, at native resolution.
  • Process-time alignment anchored on inoculation and on named phase transitions taken from the batch record, so equivalent points in the process are actually compared to each other.
  • LIMS for the offline profile and the release attributes per run: viable cell density, viability, metabolites, titer, and the product quality attributes including aggregate, charge variants and glycosylation where they exist.
  • Divergence detection as a deterministic calculation over the aligned traces, identifying where and when runs separate materially rather than trivially, with the magnitude and duration of each excursion quantified.
  • Parameter against attribute, reported as association with the strength shown and the underlying values cited. Four runs is four data points, and the output says so.

This is the workflow where it matters most to be blunt: the agent reports association, not causation. It will tell you that the pH excursion at hour 60 coincides with the runs that lost titer, and it will show you every value behind that statement. Deciding whether that is mechanism or coincidence is process science, and it stays with your scientist.

What it takes to get there

Historian access is usually the gate.

Parameter traces are the richest data in the building and often the hardest to get at programmatically. Historian access is frequently read-only through a reporting layer that downsamples, phase transitions live in the executed batch record as operator entries rather than as tags, and the join between a run identifier in the historian and a lot number in the LIMS is sometimes a manual mapping in a spreadsheet.
